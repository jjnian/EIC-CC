# 推演平台（EIC-CC）系统流程总览

> 本文档从「流程 / 数据流」角度梳理整个系统：一次请求如何在前端、后端、LLM、数据库、对象存储之间流转。
> 配合根目录 `README.md`（功能与 API 参考）一起看。
>
> 技术栈速记：**Vue 3 + Vite**（前端） / **Spring Boot 3.3 + MyBatis-Plus**（后端） /
> **PostgreSQL(+pgvector)**（结构化 + 向量） / **MinIO**（原文件对象存储） /
> **OpenAI 兼容 & Anthropic 双协议 LLM**（streaming + JSON）。

## 0. 全局请求生命周期

所有业务请求共享同一条管线：

```
浏览器 (Vue SPA :5173)
   │  fetch / EventSource
   │  HTTP REST（同步）  或  SSE（流式：对话/推演/抽取/解释）
   ▼
Spring Boot (:8000)
   │  WorkspaceInterceptor  ── 解析 X-Workspace-Id → 写入 ThreadLocal
   ▼
Controller (薄)  →  Service (业务编排)  →  Repository (MyBatis-Plus)
   │                      │                        │
   │                      ├─► LlmHttpClient ─────► 外部 LLM（OpenAI兼容/Anthropic）
   │                      ├─► EmbeddingClient ───► 外部向量模型
   │                      ├─► MinIO ────────────► 原文件/抽取文本对象存储
   │                      └─► JdbcConnector ─────► 用户外部业务库（MySQL/PG/Oracle…）
   ▼
PostgreSQL (+pgvector)
```

请求分两类：

| 类型 | 通道 | 典型端点 | 前端处理 |
|---|---|---|---|
| **同步** | HTTP JSON | CRUD、列表、配置、SQL 执行 | `api/http.ts` 统一封装 |
| **流式** | SSE（`SseEmitter`） | 对话、推演、抽取、解释、索引进度 | `useExtractStream` / `usePrediction` / `useChatSend` 解析 `event:`/`data:` |

流式端点统一用 `SsePushUtils.newCancellableEmitter(timeout)`，前端断开即触发 `cancelled` 标志，后端及时停止 LLM 轮询与逐步推送。

## 1. 工作空间隔离（贯穿所有流程）

多租户隔离不是某个功能，而是横切机制，先理解它，后面所有流程才说得通。

```
前端每个请求带 Header: X-Workspace-Id: ws_xxx
        ▼
WorkspaceInterceptor.preHandle()
        ▼
WorkspaceContext.set(wsId)   // ThreadLocal
        ▼
各 Repository SQL 自动追加 WHERE workspace_id = ?
        ▼
afterCompletion() → WorkspaceContext.clear()  // 防线程池串号
```

关键点：

- **公共库 + 引用**模型：数据源 / 经验库本身是"公共"的（`data_source` / `experience`），归属某工作空间的方式是建一条**引用**记录（`data_source_ref` / `experience_ref`）。检索、侧栏、建图都按"本空间引用"过滤——**只索引不建引用 = 召回不到**，所以代码里二者总是一起做。
- **后台线程要手动透传**：异步建图 / 索引线程没有拦截器的 ThreadLocal，必须显式把 `workspaceId` 传进去（见 `ExperienceOntologyService` 并行建图注释）。
- 删除工作空间走 `WorkspaceCascadeCleaner` 级联清理；删默认空间时自动把下一个升为默认。

## 2. AI 对话建模流程

把自然语言变成图谱增量（节点 / 边）。入口 `ChatController` → `ChatLlmService`。

```
用户在 ChatPanel 输入(可 @ 引用数据源/经验、可粘贴图片附件)
        │  POST /api/chat/stream
        ▼
ChatLlmService.chatStreaming()
  1. 空输入兜底：message 空且无附件 → 直接友好提示，不调 LLM
  2. RAG 上下文收集 (ChatContextCollector)：
       • 数据库类数据源：默认枚举本空间全部；用户 @ 显式引用则只取那些
       • 经验库：@ 指定的经验取全文(优先)，其余靠向量召回片段
       • 透传命中的 DB schema，供血缘补全
  3. GraphPromptBuilder 拼 system+user prompt（含现有 nodes/edges 让 LLM 做增量而非重画）
  4. LlmHttpClient 流式调用 LLM
        ▼
handleResponse() 解析 LLM JSON 输出：
  • add_nodes / add_edges        → 新增
  • delete (节点/边 id 列表)      → 从画布移除
  • patch (含 id 的局部修改)      → 就地更新
  • derived_tables → schema 反查 → 补全 derived_source/database/table 三段血缘
  • clarifying questions(最多4, 支持多选) → 渲染为可点选卡片
        ▼
逐个上报 build_node_* / build_edge_* step 事件（每步 sleep 70ms 制造"生长"动画）
  超过 MAX_BUILD_STEPS(24) 用 merging_graph 汇总兜底
        ▼
前端 useChatSend 接收 → useGraphEditor 应用增量 → GraphCanvas 重绘
```

边/节点的 `source` 标记：`derived`（文本明示）/ `inferred`（模型补充）/ `predicted`（推演）/ `preset`（预置）。

## 3. 因果推演流程

在已有图谱上沿因果链做正向预测或反向溯因，每次推演产出一个**分支（Scenario）**。入口 `ScenarioController` → `PredictionOrchestrator`。

```
用户选定种子节点 + intent(forward/backward) + 约束 → POST /api/scenarios/predict (SSE)
        ▼
PredictionOrchestrator.run(req, emitter, cancelled)
  1. intent 归一：非 forward/backward 一律按 forward
  2. fork 加盐：若 parentBranchId 存在，用毫秒时间戳36进制做 salt，
     给本批新增节点 id 加盐，避免与父分支冲突（IdSaltRewriter 区分"新增"vs"引用祖先"）
  3. 约束处理 (what-if)：
       • force      → 必然发生
       • block      → 剪枝该节点及其下游（全上游被 block 的节点连带剪枝，自身加入 blocked）
       • probability→ 贝叶斯先验，写入 effProb / cumCredibility 初值
  4. 坐标布局：forward 向右扩展，backward 向左
  5. 逐节点 buildStep（PredictionStepBuilder）：
       • 跨步共享上下文：blockedIds / effProb / 累积可信度 / 每步计数
       • 调 LLM 生成下一层节点+边+因果链顺序
       • 组装 SSE step 事件（每步 sleep 220ms）
  6. rawPrompt 快照：system+user 拼成可读文本写入 Scenario，供事后审计(P1-8)
  7. 剪枝明细 → notice 事件 → 前端 toast
        ▼
complete 事件携带完整 Scenario（PredictionDag：节点/边/因果链/约束/解释缓存）
        ▼
前端 usePrediction 创建新分支；BranchPicker 可在主干/各分支间切换、对比
```

分支只**增量**记录预测新增的节点/边，挂在主干或其它分支下，形成假设树。

## 4. 节点解释流程

对某个预测节点生成三段式解释。入口 `ScenarioController` → `ScenarioExplanationService`。

```
用户点开预测节点的"为什么" → POST /api/scenarios/{id}/explain (SSE)
        ▼
ScenarioExplanationService（在 predictionExecutor 线程池异步执行）
  • 取该节点的因果链上下文 → ExplainPrompts 构造 prompt → LLM 流式
  • 产出三段：依据(evidence) / 假设(assumption) / 反例(counterexample)
        ▼
结果缓存进 scenario_node_explanation（NodeExplanation），同节点再问直接命中
        ▼
前端 ExplanationPanel 流式渲染
```

## 5. 文档导入与实体抽取流程

多格式资料 → 文本 → LLM 抽取 → 图谱增量 + 落库为数据源。入口 `OntologyModelController`(抽取端点) → `DocumentExtractionService`。

```
上传文件(≤8) / URL(≤5) → SSE 抽取端点
        ▼
DocumentExtractionService.extractCore()
  1. toUploaded：字节读入内存，过滤空文件
  2. processFiles：FileProbe 嗅探(文件头+扩展名+content-type) → 派发给对应 handler
       ├─ PdfFileHandler   PDFBox：文字层；扫描件渲染成图片走视觉识别
       ├─ DocxFileHandler  POI：段落 + 表格
       ├─ ImageFileHandler ImageRecognitionService：视觉模型 OCR/识别
       │                   （未配置视觉模型 → 明确报错，不静默回退文本模型）
       ├─ AudioFileHandler AudioTranscriptionService：Whisper 转写正文
       └─ 文本/MD/CSV      直接读
  3. processUrls：urlFetchExecutor 并行抓取（限同源/只读护栏由 Agent 侧负责）
  4. ExtractionLlmService：把正文喂 LLM → add_nodes/add_edges
  5. IdSaltRewriter：毫秒时间戳salt 加 id 前缀，避免与现图冲突；salt 回传前端(便于撤销导入反过滤)
  6. persistDataSources：每个非 skipped 来源写入 data_source
       • 音频/图片(带 transcript)：按(工作空间,名称)upsert 去重
       • 转写正文落 extra_json.transcript
       • 纳入当前工作空间(建 data_source_ref) + 自动建向量索引
         → 使"图片/音频数据"可被对话召回、可抽取进经验库参与建图
        ▼
前端 useExtractStream/useImportFlow：去重(useImportDedup) → 合并(useImportMerge) → 应用到画布
```

## 6. 数据源管理流程

数据源 = 可被对话/建图引用的"供血"资料，分**文件型**与**连接型**两类。
入口 `DataSourceController` / `DataSourceFolderController` → `DataSourceService` / `JdbcConnectorService`。

```
文件型（pdf/docx/txt/音频/图片…）
  上传 → MinIO 落桶(原文件) + 抽取文本 → data_source(file_stored) → 建索引

连接型（数据库 / HTTP）
  ┌ 数据库：配置 url/账号 → JdbcConnectorService（MySQL/PG/Oracle Dialect）
  │   • 连接测试 / 库表概览(DbOverviewTab) / 表列表(DbTableListTab)
  │   • SQL 执行(DbSqlTab) → SqlExecuteResponse
  │   • Schema 透传给对话建图，补全节点/边的「数据源+库+表」三段血缘
  └ HTTP：HttpExecuteTab 即时调用 + HttpScheduleTab 定时取数
      • 每次取数写 data_source_fetch_log（HttpHistoryTab 回看）
```

数据源可放入文件夹（`data_source_folder`），归属工作空间靠 `data_source_ref`。

## 7. 经验库与建图流程

经验库（Experience）= 沉淀的 markdown 知识，可整库聚合成一张图谱。
入口 `ExperienceController` / `ExperienceFolderController` → `ExperienceOntologyService`。

```
经验 CRUD → 保存后 ExperienceIndexService.reindexAsync()（有界线程池排队建索引）
        ▼
"从经验库建图" → ExperienceOntologyService.extractFromWorkspace()
  1. 读本空间引用的经验（上限 500，超出上报跳过）
  2. 结构化直连：剥离探索文档内嵌的 <!-- EXPLORE_GRAPH {json} --> 图片段，
     直接合并(不占建图上限、免散文重抽的有损往返)
  3. 散文按字符预算分批(≈一次LLM调用/批) → 并行抽取(有界池) → 按 label 增量合并去重
  4. 结构化图谱并入 LLM 草稿 → 统一校验
  5. 全图打 derived_source=经验库 标记（区别于数据源直出图，留供血追溯入口）
        ▼
返回 {nodes, edges, reply, salt}（与 chat/extract 形状兼容）→ 前端应用到画布
```

经验也可放文件夹（`experience_folder`），归属靠 `experience_ref`。

## 8. Web 系统探索（Agent）流程

让浏览器 Agent 自动探索一个 Web 系统，产出"功能地图"经验 + 结构化图片段。
入口 `ExploreController` → `ExplorationAgentService`（驱动 `BrowserAgentDriver`）。

```
用户给 baseUrl(+可选账号密码) → POST /api/explore (SSE 进度)
        ▼
ExplorationAgentService.explore()
  1. 自动登录(若给凭据)，校验是否真登录成功
  2. 登录态有价值 → 回存 storageState（服务端侧通道，绝不回前端）下次免登录
  3. 网络护栏：拦非幂等请求(只读) + 锁定同源，防误改数据/防跑偏第三方站
  4. 会话失效检测：登录后又被重定向回登录页 → 提前结束，避免空转
  5. 循环：页面快照编码成提示 → LLM 决策下一步(广度优先，标注已访问链接避免打转)
  6. 累积功能地图：抽"事实"(表格列/表单字段)作硬信号 → 渲染成 markdown 经验
  7. #1 结构化直连：把页面/对象/属性结构化成图片段，以隐藏 HTML 注释嵌进文档末尾
     （人看 markdown 不受影响；建图侧机器可解析、直接合并）
        ▼
产出经验存入经验库 → 后续可走第 7 节"经验库建图"直接成图
```

前端 `useWebSystemExplore` 驱动，URL 归一化（去 query/hash、数字路径段换 `:id`）把同类详情页折叠成一页。

## 9. 向量索引与 RAG 检索流程

为数据源 / 经验库提供语义检索，支撑对话 RAG。
`DataSourceIndexService` / `ExperienceIndexService` + `EmbeddingClient`。

```
建索引（保存/上传后异步触发，未配置 embedding 则静默跳过）
  正文 → 结构感知切块(按 Markdown 标题层级 + 大小约束)
       → 增量复用：同模型下内容哈希未变的块复用旧向量，只对新增/改动块调 embedding
       → batchUpdate 批量入库（exp_chunk/ds_chunk + exp_embedding/ds_embedding）
       → pgvector 可用时回填 vector 列（尽力而为，维度不符则忽略）
  backfillUnindexed()：补索引落桶文件 + 带 transcript 的来源(音频等)

检索（对话 RAG 时调用）
  searchRelevant(workspaceId, query, topK)
    • pgvector：HNSW 近似最近邻，cosine 算子 <=>，score = 1 - 距离
    • 无 pgvector：TEXT 向量暴力余弦兜底
    • 公共库口径：只召回「本工作空间引用」的数据源/经验（与侧栏/建图一致）
```

检索结果片段在第 2 节对话流程里被注入 prompt 上下文。

## 10. 节点供血绑定流程

把图谱节点绑定到具体数据源，让节点"活"起来（可实时取数）。
入口 `NodeBindingController` → `NodeDataBindingRepository` + `DataSourceService`。

```
列出绑定：GET  /api/node-bindings?modelId=&nodeId=
新建绑定：POST /api/node-bindings   (节点 ↔ 数据源/查询)
取数：    GET  /api/node-bindings/{id}/fetch  → 走 DataSourceService 拉实时数据
```

存表 `node_data_binding`。前端 `NodeDataBindingPanel` 展示，建图来源(derived_source)为这条追溯链留了入口。

## 11. 版本快照与回滚流程

本体模型的"时光机"。入口 `OntologyModelController`(版本端点)。

```
关键修改 → 自动快照：把当前 nodes/edges/props 复制进版本表
  ontology_model_version / ontology_version_node(_prop) / ontology_version_edge
        ▼
查看版本列表 → 选某版本 → 回滚：用版本表覆盖主表
        ▼
分支对比(BranchCompareDialog)：主干 vs 分支 增量 diff
```

注意区分两条"历史"线：

| 机制 | 范围 | 存储 |
|---|---|---|
| **撤销/重做** | 前端单次会话内的画布操作 | `useGraphHistory`（内存栈） |
| **版本快照** | 跨会话的模型级备份/回滚 | DB 版本表（持久化） |

## 12. 数据存储全景

**PostgreSQL**（`init.sql` 启动幂等建表 + 轻量迁移，`schema_migration` 记录版本）：

| 域 | 主要表 |
|---|---|
| 工作空间 | `workspace` |
| 本体图谱 | `ontology_model` / `ontology_node` / `ontology_node_prop` / `ontology_edge` |
| 版本快照 | `ontology_model_version` / `ontology_version_node(_prop)` / `ontology_version_edge` |
| 推演分支 | `scenario` / `scenario_seed` / `scenario_node` / `scenario_edge` / `scenario_chain_step` / `scenario_constraint` / `scenario_node_explanation` |
| 对话 | `conversation` / `conversation_message` |
| 模板 | `graph_template` / `hypothesis_template` |
| 数据源 | `data_source` / `data_source_folder` / `data_source_fetch_log` / `ds_chunk` / `ds_embedding` |
| 经验库 | `experience` / `experience_folder` / `exp_chunk` / `exp_embedding` |
| 关联 | `node_data_binding` / `experience_ref` / `data_source_ref` |

**MinIO**（对象存储桶 `tuiyan`）：数据源原文件（pdf/docx/txt/音频/图片）+ 抽取文本统一落桶。

**pgvector**：`*_embedding` 表的 `vector` 列，做 HNSW 近似最近邻；不可用时回退 TEXT 向量余弦。

> 注：README 早期版本提到「本地 JSON 文件 `~/.tuiyan/`」，当前实现已迁移到 PostgreSQL + MinIO；`~/.tuiyan` 仅用于少量本地配置/缓存。

## 13. LLM 适配层

统一封装在 `service/llm/` 与 `EmbeddingClient`：

```
业务 Service
   │ 选模型(LlmConfigResolver：内置 application.yml 模型 + 用户自定义配置)
   ▼
LlmBodyBuilder  ── 按协议组请求体（OpenAI 兼容 / Anthropic 原生）
   ▼
LlmHttpClient   ── Java HttpClient 发请求；流式逐块读
   ▼
LlmStreamParser ── 解析 SSE chunk，拼出增量文本 / JSON
   ▼
LlmCallLogger + LlmMetricsService ── 记录调用、token、耗时（SystemController 暴露指标）
```

内置模型（`application.yml`，可在设置页覆盖）：DeepSeek V4 Flash/Pro（建模主力）、Whisper-1（音频转写）、GPT-4o（图片识别），均支持环境变量覆盖 base URL / key / model-name。

## 14. 启动与部署流程

```
前置：JDK17+、Node18+、PostgreSQL(执行 init.sql 自动)、MinIO、LLM API Key
        ▼
./start.sh
  ├─ 杀掉 8000/5173 旧进程
  ├─ backend:  mvn spring-boot:run        → :8000（启动时跑 init.sql 建表/迁移）
  └─ frontend: npm run dev (Vite)         → :5173
        ▼
浏览器访问 :5173；前端 fetch 打到 :8000
```

配置入口：环境变量（`DEEPSEEK_API_KEY` / `DB_URL` / `MINIO_*` / `VISION_MODEL` / `ASR_MODEL` …）
或 Web 设置页（`SettingsView` → ModelsTab/DataTab/PredictTab…，运行时增改模型配置、连接测试）。

## 附：核心概念速查

| 概念 | 一句话 |
|---|---|
| 本体模型 OntologyModel | 一张图谱画布（nodes/edges + 版本） |
| 主干 trunk | 图谱的"真实"状态 |
| 分支 Scenario | 一次推演的增量快照，挂在主干/其它分支下 |
| intent | forward(因→果) / backward(果→因) |
| 约束 constraint | force / block / probability，用于剪枝或概率融合 |
